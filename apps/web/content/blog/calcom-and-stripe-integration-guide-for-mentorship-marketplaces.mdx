Mentorship marketplaces require flawless coordination between scheduling and payments. Cal.com creates deep availability controls, while Stripe Connect manages payouts and compliance. Discuno stitches both systems together with opinionated defaults that you can adapt to your own stack. This guide explains the reference architecture and shares implementation tips.

## Architecture Overview

```
Mentee ➜ Discuno (Next.js 16) ➜ Cal.com API ➜ Booking Webhooks
                                  │
                                  └➜ Stripe Checkout ➜ Stripe Connect Payouts
```

- **Frontend:** Discuno’s Next.js 16 app renders dynamic scheduling flows with React Server Components and Tailwind CSS.
- **Backend:** Drizzle ORM (PostgreSQL) stores bookings, mentors, and payout states with audit logs.
- **Integrations:** Cal.com handles availability. Stripe Connect powers payments. PostHog logs analytics across both flows.

## Cal.com Integration Pattern

1. **Organization users:** Discuno provisions eligible mentors in a Cal.com organization and manages their team membership and default schedule from the server.
2. **Event types:** Each mentorship format (intro session, project review, career roadmap) maps to a Cal.com event type with custom forms and location rules.
3. **Webhooks:** Cal.com webhooks hit `apps/web/src/app/api/webhooks/cal/` to persist bookings, attendees, reschedules, no-shows, and cancellations. Discuno verifies each HMAC signature and makes state transitions idempotent.
4. **Server credentials:** A server-only organization API key replaces the deprecated per-user OAuth-token flow. No Cal.com credential is returned to the browser.

## Stripe Connect Integration Pattern

1. **Session pricing:** Discuno stores prices on mentorship event types and builds Stripe Checkout line items server-side.
2. **Checkout session:** The mentee is routed through Stripe Checkout using signed URLs generated server-side with Zod validation.
3. **Platform charge:** Checkout charges on Discuno’s platform account. The mentor transfer is deliberately separate so cancellations, refunds, and disputes can be resolved before funds move.
4. **Durable fulfillment:** Signed Checkout webhooks persist the payment once, then enqueue retry-safe Cal.com booking work through Inngest. Both immediate and asynchronous payment success events use the same fulfillment path.
5. **Failure recovery:** If Cal.com booking creation ultimately fails, Discuno refunds the PaymentIntent and alerts support if the refund needs manual intervention.

### Sample Payout Flow

```typescript
await stripe.checkout.sessions.create({
  mode: 'payment',
  line_items: [{ price_data: sessionPrice, quantity: 1 }],
  payment_intent_data: {
    transfer_group: bookingTransferGroup,
  },
})

// After the session and support window:
await stripe.transfers.create({
  amount: mentorAmountInCents,
  currency: 'usd',
  destination: mentor.stripeAccountId,
  source_transaction: stripeChargeId,
})
```

## Security and Compliance Considerations

- **Least privilege:** Integration secrets remain server-only and are scoped independently for local, preview, and production environments.
- **Webhook integrity:** Cal.com and Stripe requests are rejected unless their signatures validate against the raw request body.
- **Auditability:** Canonical payment and booking state is stored with timestamps and provider IDs, and webhook replays are idempotent.
- **Tax:** Stripe Automatic Tax is enabled at Checkout. Marketplace operators should still confirm their own filing and connected-account obligations with qualified advisers.
- **Privacy:** Better Auth keeps email and Google sign-in behind the same server-side session and role controls.

## Monitoring and Observability

- **PostHog dashboards** track conversion rates from session selection to completed payment.
- **Administrative alerts** notify the configured support address when a failed refund, reversal, or payout requires manual review.
- **Inngest runs** let support teams trace payment fulfillment, Cal.com booking retries, refunds, and alerts.
